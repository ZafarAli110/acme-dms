# Plans

One file per ticket in progress, written by the `ticket` skill and named by when it was created:
`<YYYY-MM-DD>_<HH-MM>_<KEY>_<short-name>.md`. It opens with what a reader needs first: the status and what happens now,
the requirement, and the acceptance criteria as the goal. Then the skills and standards to load, the shape (the feature
it follows, the files, high-level code), the tests and the steps. The questions, decisions and log come last. About 150
lines at most: a plan is for a person to read. It lets work continue after the conversation is compacted, the session is
restarted, or someone else picks it up. A session-start hook lists the plans not done yet, with their status.

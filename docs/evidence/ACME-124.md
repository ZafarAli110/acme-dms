## What these checks don't prove

- **A location with no parts** ("No parts stocked at …", total 0, value 0) was not checked in the running system: no
  location is empty in the sample data. The stock value's handler test covers $0.00 at a location with no stock; the
  count's 0 is covered only for a search with no match. Needs a test with an empty location.
- **The speed rows are the author's runs, on one laptop**, not the verifier's: its run was cut short when the
  containers restarted. The tails swing run to run (parts search p95 322 to 559 ms across two runs, its p50 steady).
- **Description is the slowest sort** (21 ms warm, it reads `parts` whole) and the bin sort 27 ms: fine at 24,000
  stocked parts, worth re-measuring for a location that stocks far more.
- **One worker under heavy load:** stock value and the count use Postgres's parallel workers when free (14 ms); with
  none free they take 26 to 29 ms. A run past 200 a second would show whether workers run short.
- **The verifier's throwaway data stays at Northside** (parts 0VFY124-1…6, bins VFY124-LIVE and VFY124-GONE); they sort
  first on the default list until `bun run reset`.

## What these checks don't prove

- **No save was answered busy by the real system.** Saves keep their own connections (ACME-121), and 85 adds during
  two runs at 450 a second all saved. The busy save was checked in the running app with the busy answer put in by the
  browser, in ACME-121's shape; if the server's busy answer ever changes shape, only the unit test would notice.
- "Twice the rate the system handles" was run at 450 a second, not 300: the work since ACME-121 raised the laptop's
  capacity, so 300 is no longer busy here.
- Under real overload "still busy" comes after about 7.5 s, not about 3: each busy answer itself takes up to the
  list's 1.5 s connection wait. The line shows from the first busy answer, so the person is never left with a bare
  spinner; whether 7.5 s is acceptable at the desk is a person's call.
- The test runs left customers named "Verify…", "Busyday", "Livecheck" and "Loadtest" at Northside.

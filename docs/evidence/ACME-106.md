## What these checks don't prove

- **Size.** The customer list the verifier saw had 400,007 rows (not checked whether that is one location or all). The query filters by dealer and location and sorts by last
  contact date; no row above shows its time, and no index on those columns was looked at. The performance reviewer
  should read the query plan. Needs a person or a test.
- **"In the Customers list" is proved by a search, not by comparing the two lists name by name.** The list is too big to
  page through. The search finds the id, which shows the customer is in the list, but not that the list and "recent"
  use the same rule for everything else (a status filter, say). Nothing more needed unless the list's rules change.
- **Maria's Home screen was not screenshotted**, only Sam's. The change is backend-only and Maria's data was checked
  through the API, but nobody has looked at her Home page. Needs a person, or a Playwright test.
- **Only one dealer pair was tried.** Tom is the one City Motors user; a second dealer with several locations was never
  seeded. The handler test also covers the dealer filter alone (a Northwind user at Central's location), which the API
  calls cannot.
- **The end-to-end suite (`gate:slow`) was not run.**
